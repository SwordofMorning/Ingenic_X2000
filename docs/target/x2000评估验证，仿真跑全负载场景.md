# x2000评估验证，仿真跑全负载场景

一、媒体通路模块：

[1.VI](http://1.VI)，DVP接口：640x512@50fps，UYVY格式采集；

2.VO，MIPI-DSI接口，1440x1080@50Hz时序，RGB24格式输出；

2a.视频层1需从 640x512 放大到 1440x1080；

2b.视频层2需从 640x512 裁剪 160x128 或者更小分辨率，等比例放大到 480x360，居中置顶显示；

2c.图形层1映射framebuffer，ping-pong双buffer缓存，画布分辨率：1440x1080，格式：ARGB8888；由QT绘制刷型；

2d.VO内部自处理，YUV转ARGB，MIX双图层合成RGB24位图；

二、UI交互模块

1.QT动态绘制多种图形及大倍率枪瞄十字资源图标，随机移动坐标；

三、编码模块\(VPU最大编码能力1920x1080@30fps\)

1.编码通道1（带UI信息），每两帧（50fps/40ms），相当于1440x1080@25fps，获取VO合成后的RGB24位图，调用MSA完成RGB24转NV12格式，并送VPU完成h.264/h.265编码处理；

2.编码通道1编码数据（1440x1080@25fps），内存缓存5s编码数据，持续刷新覆盖最旧缓存，始终保持最新的5s视频编码缓存；

3.编码通道2（不带UI信息），每两帧（50fps/40ms），1440x1080@25fps，获取VO视频层NV12叠加图，并送VPU完成h.264/h.265编码处理；

4.编码通道3，每秒1帧，获取VO合成后的RGB24位图，1440x1080，RGB888格式，调用MSA完成RGB24转NV12格式，并送VPU完成MJPEG编码处理，并写eMMC保存.jpg文件；

四、录制推流模块

1.根据rtsp点播请求，获取对应编码通道的264/264编码码流，封装RTP推流播放服务；

2.获取编码通道1数据，完成MP4封装，长时间持续录制，写eMMC保存.mp4文件；

3.每30s，获取编码通道1的前5s缓存编码数据，加上后续10s，封装保存为单独.mp4文件；

4.UVC出编码后的YUV/RGB/h264;

五、系统稳定性

1.长时间运行稳定性；

2.高低温启动/运行稳定性：

3.图像显示会不会掉帧或者其他异常；

4.编码录制会不会掉帧或者其他异常；

5.系统CPU、DDR的内存负载占耗监控；

---

1. 图像输入：当前DVP红外摄像头输入是640x512的分辨率，其中左半边数据是AD数据，分辨率是640x512，右半边是YUV数据，分辨率也是640x512。
2. 图像输出：显示LCD的分辨率是640x480，所以显示的时候，输入的640x512分辨率转为640x480进行显示，帧率可以达到50fps。
3. OSD显示： 可以叠加osd文字叠加到画面上，帧率50fps。
4. h264编码和MP4文件保存：将640x512的分辨率使用ISP放大到1280x1024后，25fps可以保证h264编码正常，MP4文件也正常。但是到40fps以上，编码因吞吐量（带宽）限制导致uv分量编码后异常，MP4文件播放画面颜色异常。
5. rtsp码流和WIFI传输经过验证也是可行的。rtsp编码视频分辨率为1280x1024，帧率25fps。

---

x2000评估验证，仿真跑全负载场景，长时运行稳定性，高低温启动/运行稳定性：

1. VI-VO满帧率50fps，VO按屏幕全分辨率出；
2. 图形层叠个时间日期，再随机画点东西；
3. 按屏幕全分辨率，50fps，从VO获取叠加后的RGB图，使用MSA完成RGB转NV12，再送VPU编码录制成.mp4;
4. 另起一路，拿VPU编码好的码流，通过wifi走RTSP推流，PC端点播实时预览；

---

看看跑起来的稳定性，图像显示会不会掉帧或者其他异常，编码录制会不会掉帧或者其他异常，以及系统CPU、DDR的内存负载监控；
